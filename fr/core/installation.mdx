<Warning>
Cette page documente le candidat de développement `0.8.3`. Sa version runtime
n'est pas encore publiée. Ne pas appliquer ces instructions à l'ancien paquet
`0.8.2` sans vérifier le manifeste de cette version.
</Warning>

## Prérequis

- un serveur Open2077 compatible avec `open77_version ">=0.0.1"` ;
- une base MariaDB joignable depuis le processus du serveur dédié ;
- l'accès à `server.jsonc` et la possibilité de redémarrer tout le serveur.

`bt_core` ne dépend d'aucune autre ressource BT CORE.

## 1. Charger la ressource

Placer la version dans `resources/bt_core/`, puis ajouter `bt_core` à la liste
`resources.load` existante. Fusionner cette entrée sans remplacer le reste du fichier.

```jsonc
{
  "resources": {
    "enabled": true,
    "root": "resources",
    "load": [
      "open77_*",
      "bt_core"
    ]
  }
}
```

## 2. Choisir une seule méthode de connexion

`connectionString` et `connectionStringEnvironmentVariable` sont **deux moyens
de fournir la même connexion**, pas deux chaînes à remplir.

### Option A — Variable d'environnement (recommandée)

Conserver le mot de passe hors de `server.jsonc` :

```jsonc
{
  "database": {
    "enabled": true,
    "connectionString": "",
    "connectionStringEnvironmentVariable": "OP77_DATABASE_CONNECTION",
    "maxRows": 10000
  }
}
```

`connectionStringEnvironmentVariable` contient le **nom de la variable**, pas
le mot de passe ni la chaîne de connexion MariaDB. Définir cette variable avant
de lancer le serveur dédié.

<Tabs>
  <Tab title="Windows PowerShell">
    ```powershell
    $env:OP77_DATABASE_CONNECTION = 'Server=127.0.0.1;Port=3306;Database=open77rp;User ID=bt_core;Password=REMPLACER_PAR_UN_MOT_DE_PASSE_UNIQUE;'
    # Lancer le serveur dédié Open2077 depuis cette session PowerShell.
    ```

    Cette valeur dure pendant le processus PowerShell courant et ses processus
    enfants. En production, configurer le secret pour le compte ou le service
    qui lance Open2077.
  </Tab>
  <Tab title="Linux">
    ```bash
    export OP77_DATABASE_CONNECTION='Server=127.0.0.1;Port=3306;Database=open77rp;User ID=bt_core;Password=REMPLACER_PAR_UN_MOT_DE_PASSE_UNIQUE;'
    # Lancer le serveur dédié Open2077 depuis ce shell.
    ```

    En production, utiliser le gestionnaire de secrets de systemd, du runtime
    de conteneur ou du panneau d'hébergement.
  </Tab>
</Tabs>

### Option B — Valeur directe dans `server.jsonc`

Utiliser cette solution uniquement si l'hébergeur ne peut pas injecter de
variable d'environnement :

```jsonc
{
  "database": {
    "enabled": true,
    "connectionString": "Server=127.0.0.1;Port=3306;Database=open77rp;User ID=bt_core;Password=REMPLACER_PAR_UN_MOT_DE_PASSE_UNIQUE;",
    "maxRows": 10000
  }
}
```

<Warning>
Cette méthode stocke les identifiants en clair. Ne pas versionner `server.jsonc`
et limiter son accès à l'opérateur et au compte de service.
</Warning>

## Quelle valeur est utilisée ?

Le bridge de base de données Open2077 applique cet ordre :

1. une valeur non vide dans `database.connectionString` ;
2. sinon, la valeur de la variable nommée par
   `database.connectionStringEnvironmentVariable` ;
3. si `database.enabled` vaut `true` et qu'aucune source ne fournit de chaîne,
   la validation de démarrage échoue.

Le nom de variable par défaut est `OP77_DATABASE_CONNECTION`. La valeur doit
respecter le format **MySqlConnector** séparé par des points-virgules montré
ci-dessus, et non une URL `mysql://` ni une directive FiveM
`set mysql_connection_string`.

<Note>
Redémarrer tout le serveur dédié après une modification de la base. Recharger
uniquement `bt_core` ne recrée pas le bridge de base de données du serveur.
</Note>

## 3. Préparer et vérifier MariaDB

1. Créer la base `open77rp` si elle n'existe pas.
2. Créer un compte MariaDB dédié avec les seuls droits nécessaires sur cette base.
3. Démarrer le serveur dédié Open2077.
4. Confirmer la connexion du bridge et l'état prêt de `bt_core`.
5. Terminer l'onboarding d'un personnage test, se reconnecter et vérifier la persistance.

`server/db.lua` crée ou migre automatiquement :

- `bt_core_characters` ;
- `bt_core_ledger` ;
- `bt_core_character_jobs` ;
- `bt_core_vehicles`.

`sql/001_bt_core.sql` est une référence lisible ; ne pas l'exécuter à chaque démarrage.

## Ordre de chargement

Charger `bt_core` avant toute ressource qui appelle ses exports. Ajouter chaque
future ressource BT CORE après ses dépendances déclarées.
