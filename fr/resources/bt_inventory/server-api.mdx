Les exports s'appellent avec
`Open77.exports.call("bt_inventory", nom, ...):await()`.

## Objets runtime

```lua
local item = Open77.exports.call("bt_inventory", "registerItem", {
    name = "example:medkit",
    label = "Example Medkit",
    usable = true,
    stackable = true,
    stackLimit = 10,
    consumeOnUse = 1,
    imageName = "example_medkit.png",
    useExport = "useExampleMedkit",
}):await()
```

Exports : `registerItem`, `unregisterItem`, `getRegisteredItem`,
`listRegisteredItems`.

## Inventaires enregistrés

Une définition accepte `id`, `name`, `slots`, `limit`,
`acceptItems`, `acceptWeapons`, `shared` et `whitelist`.

Exports : `registerInventory`, `inventoryExists`,
`getInventoryDefinition`, `updateInventory`, `deleteInventory`,
`setInventoryInstanceLimits`.

## Contenu

- lectures : `getInventory`, `getInventoryUsage`, listes et compteurs ;
- mutations : ajout/retrait/set objet, armes, transferts, `moveEntry`,
  `splitStack`, `mergeStacks`, `autoSort` ;
- UI : `openInventory(playerId, inventoryId, scope)`.

Seul le propriétaire de la définition peut la muter. Les options publiques
suppriment tout drapeau de privilège interne. Utiliser un `operationId`
stable et unique, ainsi que les révisions pour la concurrence optimiste.

Les helpers joueur couvrent snapshots, listes, compteurs, ajout/retrait
d'objets ou armes et limites RPG de slots/unités modifiables à chaud.
Le personnage doit être attaché par `bt_core`, avec une seule session active.
